# Polaris 总览

## 它是什么

你写一条需求，Polaris 在你自己的机器上拉起一个真实的 coding agent（Claude Code），它把文件直接写进你的项目目录。

它不是聊天框。一条需求就是一次运行：提交即开跑，中途不能追问、不能补充。想改，就再提一条新需求。

一次运行只有一个 agent 在干活。

Polaris 自己没有账号、没有服务器：项目、任务、文件都只在你的机器上，agent 进程也在本机。Coding agent 随应用一起分发，你不需要另外装 Node，也不需要预装 Claude Code。

## 动手之前

三件事必须先说清楚。它们都不是「以后会改」，是今天的事实。

### 它要联网，你的代码会离开这台机器

agent 要调模型。所以你的需求正文、以及它为了干活而读到的项目文件内容，会被发送到你在设置里配的那个模型服务商（Anthropic 官方 / DeepSeek / 你自己填的 Anthropic 兼容端点）。

没有本地模型这条路。不能外发的代码，不要交给它。

### 它花的是你的钱，而界面不显示花费

用的是你自己的 API key，所以每一次运行都按你的账单计费。Polaris 里看不到任何真实用量或花费 —— 要看请去服务商后台。

「团队」页上那些 token 数字、成功率、任务数都是演示数据，不是你的真实消耗。

### 它不是沙箱

Agent 是当场写盘的 —— 没有「先给你看一眼、你点同意再落盘」这一步。而且它不止会写文件：Claude Code 自带命令执行工具，Polaris 会自动放行它的每一次权限请求，没有可关的开关，也不会弹窗问你。

它经文件通道写文件时确实被限制在项目根目录内。但它经命令通道执行的命令不受这条限制：可以在任意目录运行、往任意目录写盘，也能读到进程环境里的变量（其中就有你的 API key）。

> 说白了：在你这个账号的权限之内，它想做什么，Polaris 都拦不住。请只在你信得过这个 agent、并且有版本控制的目录上用它。Polaris 提供的不是沙箱。

## 快速开始

1. 配一个 API key。没配时应用顶部有一条提示条，点它；或者点侧栏页脚的「设置」。可以选 Anthropic 官方、DeepSeek，或任意 Anthropic 兼容端点（自定义）。改完 key，后端会自动重启。
2. 建一个项目，或者打开一个已有的文件夹。启动页上是「新建项目」与「打开项目 → 从文件夹打开」。你在系统对话框里亲手选中的那个目录，就是 agent 的工作区。
3. 提需求。在侧栏里展开项目，把鼠标移到「任务」那一行，点它右边的 ＋；或者用任务页右上角的「新建需求」。说清你想要什么，点「创建任务」—— 它立刻开跑，没有二次确认。
4. 看产出。顶部的主句说明现在正在发生什么；步骤轨的「产出」卡列出 agent 登记了哪几个文件；文件那时已经在你的项目目录里了。

打开项目后落在「团队」页。那一页是演示数据，选谁都不会改变实际执行（见已知限制）—— 直接点「新建需求」就行。

「验收标准」这一栏今天不会送到 agent 那里：后端只接收需求正文。想让它遵守某条标准，就把那条标准写进需求描述里。

> 别在项目行上找 ＋：那一行悬停出来的两个按钮是「导出运行记录」和「删除项目」。＋ 在展开后的分组行上 —— 「任务」行的 ＋ 是新建需求，「文件」行的 ＋ 只是往界面的树里插一个空节点，不会动磁盘。

## 一次需求会经历什么

后端一次运行会发出 20 余条事件。界面把它们汇聚成几个语义步骤，只有真的发生过的步骤才会出现在步骤轨上。

### 需求受理

后端建任务、建运行，立刻开跑。没有「先分析、等你确认了再动手」这一步。

### 分派与上下文

机器内部的握手。这一步展示的 ContextPack 今天是个占位常量：每次运行都一模一样，而且它并没有被喂给 agent。别把它当成记忆。

### Agent 执行

真的拉起 Claude Code，真的开始写文件。

这一段可能是几十秒到几分钟，而后端在这段时间里一条事件都不发。所以界面是静的，只有秒表在走。这是正常的，不是卡死。

### 产出

agent 每调用一次它的写文件工具，后端就登记一个产物。步骤轨上这张「产出」卡列出的，就是这些文件名。

但它不等于全部。agent 也可能是用命令把文件落到盘上的（跑一个脚手架、`git`、输出重定向）—— 那种写法不登记任何产物：产出卡会是空的，运行甚至会因为「没有可选产物」被判失败，而文件其实已经好好地躺在你的项目里了。

所以：要确认它到底动了哪些文件，以磁盘为准 —— 去项目目录里看，或者 `git status`。

### 审查

Gate。出厂配置里只挂了一条空检查，它放行一切代码 —— 不看代码、不跑测试、不做安全审查。不要把这一步当成一道关卡。

### 交付

运行结束。这里那句「已交付 N 个文件」不是 agent 写的源码数量（见已知限制）—— 它恒为 1，指的是一条元数据记录。要知道它写了哪些文件，看「产出」那一步，以及磁盘。

还有一个「议会」步骤，只在合议模式下才有。今天的真实运行不会触发它，所以你不会在步骤轨上看到它。

> 步骤轨只画后端真的发过事件的步骤：没触发的步骤不会以「灰色待办」的样子提前出现。界面不预告未来，后端没给的字段也一律留空，不编。

## 文件去了哪

agent 写的文件，落点是当前项目的根目录（后端把它叫做工作区）。

它是当场写进去的，不是跑完再拷贝。所以：即使这次运行最后报了失败，文件也可能已经躺在你的项目里了。

- 「从文件夹打开」的项目：就是你在对话框里选的那个目录。
- 「新建项目」且没选保存位置：落在系统「文档」目录下的 `polaris-workspace/<项目名>`（项目名里的 `\ / : * ? " < > |` 会被换成 `_`，所以目录名不一定与项目名逐字相同；Linux 上「文档」目录随系统设置走，可能就是你的主目录）。

怎么定位到具体的文件：

- 步骤轨的「产出」卡里有文件名。
- 点开文件页：头部第一行是它在项目里的相对路径，下面那行灰字是绝对路径（只有磁盘上真有这个文件时才显示）；右上角的文件夹图标能在系统文件管理器里定位它。文件页是只读的，不能编辑。

左侧的文件树不是磁盘的实时镜像。它是打开项目那一刻扫出来的一张快照，没有监听、不会自动刷新，也没有刷新按钮。运行结束后，树上只会补挂一个文件（后端只把选中的第一个产物带进快照）—— agent 写了五个，树上也只多一个。

想让树跟上磁盘，只能把这个项目从侧栏删掉（不会删磁盘上的文件）再重新打开一次。重新「打开」同一个文件夹是不够的：路径相同时应用会直接切回原来那个项目，不重新扫盘。

文件树上的「添加文件」和删除，只改界面里的这棵树，不动磁盘。删除项目同样不会删磁盘上的文件。

> 前端不参与写文件。它只是在事后，把后端登记过的产物挂进树里。所以「树里有什么」永远不等于「磁盘上有什么」—— 有分歧时，磁盘是对的。

## Python 终端

Dock（底部面板）的「终端」频道里是一个受限的 Python 执行器：它只能跑当前项目里的 `.py` 文件，或者打开一个交互式 Python。它不是系统 shell，打不了任意命令。

它的工作目录就是项目根目录 —— 和 agent 写文件的目录是同一个。

三个入口：文件树里 `.py` 那一行悬停时出现的 ▶、文件页右上角的「运行」、终端频道标签栏上（以及空态里）的「打开交互式 Python」。

要提醒一句：前两个入口都长在文件树上，而树上只补挂得到一个产物（见上一节）。agent 写的脚本如果没出现在树里，你就点不到它的 ▶ —— 得先把项目删掉重开，让树重新扫一遍盘。

要先有一个解释器。在 Dock 的「运行时」频道里选一个系统已装的，或者让 Polaris 装一个独立的。下载体积分平台，差得很远：Windows x64 约下载 45 MB、安装后 126 MB；macOS（Apple Silicon）约 24 MB / 67 MB；Linux x64 约 114 MB / 318 MB。以「运行时」频道里显示的数字为准。

Python 终端永远不会自动运行任何脚本：这里的每一次执行都必须由你亲手点一下，没有文件监听，也没有事件驱动的自动重跑。

装第三方包、中断、输出截断这些细节，看「Python 终端」那一篇。

> 为什么不给一个真正的 shell：这个终端的执行权是焊死的 —— 只能跑你亲手点的、项目目录里的一个 `.py` 文件，用你亲自选定的那个解释器，而且它拿不到 `ANTHROPIC_*` 之类的环境变量。这是为了让「Polaris 界面上的执行」永远由你发起。注意这条边界管的是你这一侧，它并不限制 agent —— agent 有自己的命令执行通道，见「动手之前」。

## 观测：你能看到什么

先认一下界面上这几块在哪：

- 主句：顶部那一行。谁、在做什么、多久了、成没成。
- 进度缎带：主句下面那条。受理 / 执行 / 审查 / 交付，现在走到哪一段。它的分母是「目前已经出现过的步骤数」，会随运行推进而增长 —— 它不是完成度百分比，也预测不了还剩多少活。
- 步骤轨：一步一张卡，卡上的摘要全部取自后端事件原文。上面那张「产出」卡，就是全文反复让你去看的那张。
- 产出面：中央那一大块。agent 干活那几十秒它是静的，因为后端在那段时间不推事件 —— 界面会把这句话直接写给你看，而不是转一个假装在忙的圈。
- 折叠列：右栏。这一步的细节、产出、交付、机器握手、你提的需求原文，以及报 bug 时要用的 run_id 和 task_id。
- Dock：底部面板。点状态栏最左边那个写着「终端」的把手，或者按 Ctrl+`（Mac 上 ⌘`）。里面三个频道：终端、事件流、运行时。
- 状态栏：最底下那一条。离开运行页之后，它是唯一还在告诉你「那个 run 是不是还在跑」的地方。它还带着事件通道的状态灯和当前的 Python 解释器。

原始事件在 Dock 的「事件流」频道里。这是全应用唯一显示事件原文的地方，最多显示 1000 条，超了会明说省略了多少条。

事件通道的三个状态，回答的是同一个问题：界面不动，是没事发生，还是断了。

- 已连接：通道活着。界面不动就是后端确实没事发生（多半是 agent 正在干活）。
- 连接中：后端进程正在起来。
- 已断开：收不到新事件了。

后端进程一旦退出或重启，所有还在跑的运行会被就地标成失败，并写明原因。宁可如实报一次失败，也不留一个永远转圈的「执行中」。

状态栏上的「事件 N」是最近的观测窗口计数（跨运行累计，封顶 200 条），和折叠列里那次运行的事件条数不是同一个口径 —— 提了第二个需求之后，这两个数字就对不上了。

侧栏项目行上的卷轴图标可以导出一份运行记录（JSON，落在项目根的 `.polaris/` 下）。它是一份只读的审计快照：不能导回应用，也不含 agent 的对话正文。

## 已知限制

- 人挡不住 agent。没有「写文件前先问你一句」这一步。agent 的权限请求由 Polaris 自动放行，没有开关。审查（Gate）由后端自己裁决完再告诉界面，而出厂配置下那条检查放行一切。界面上也没有能把你的决定送回后端的通道，所以不给同意 / 拒绝按钮 —— 一个只改本地状态、送不到后端的按钮，会让你以为自己影响了 agent。
- Polaris 不是沙箱。agent 经文件通道写文件被限制在项目目录内，但它还有一条不受限制的命令执行通道：任意命令、任意目录，并继承宿主的全部环境变量（含 API key）。目录级的边界只在文件通道上成立。
- 你的代码会发给模型服务商。需求正文和 agent 读到的文件内容都要出网。没有本地模型选项。
- 花费不可见。运行按你自己的 key 计费，而界面上没有任何真实用量或花费显示。
- 没有取消按钮。协议里有 `run.cancel`，但驱动没有实现中断，送过去也停不住 agent 进程。想停下来只能退出应用（退出会杀掉整棵进程树，包括正在写文件的 agent，写了一半的文件会留在磁盘上）。
- 多个需求不会并行，是排队。所有运行在「Agent 执行」这一步是串行的：后端按角色排一条 FIFO 队列，而所有运行都是同一个角色。第二个需求要等第一个跑完。更麻烦的是：后端不发排队事件，界面显示不出「排队中」，你只会看到一个已经在走的秒表 —— 那段时间它一秒都没跑。
- 不能跨项目并行。agent 的工作区是后端的全局状态，换项目要重启后端，而重启会把正在干活的 agent 一起杀掉。所以只要还有别的项目的运行在跑，在当前项目提需求就会被拒绝，并告诉你是哪一条需求挡住了。（只是切过去看看文件是安全的，不会杀掉它。）
- 看不到 agent 的文字回复正文。它的消息在接入层就被降维成字符数丢掉了。agent 只回复文字、不写文件时，那段内容（包括贴在回复里的代码）在界面上看不到。
- 不能追问。一条需求 = 一次运行，提交即开跑，中途没有任何向它发消息的方法。
- 产出卡只认写文件工具。agent 用命令落到盘上的文件不会被登记成产物 —— 产出卡为空，运行还会因为「没有可选产物」被判失败，而文件其实已经写好了。别把「产出卡是空的」读成「它什么都没写」，先看磁盘。
- 「已交付 N 个文件」不是 agent 写的文件数。这个数来自后端的交付报告，而交付报告数的是工作树里的一条元数据记录 —— 今天恒为 1，列出来的是一个 `.json` 路径。
- 文件树只补挂一个文件，而且不会刷新。后端只把选中的第一个产物带进快照，其余的不会出现在树上；树也没有刷新按钮，重新打开同一个文件夹不会重新扫盘。
- Agent 执行失败时，那一步的卡片仍然显示成完成。后端在失败时发的是「执行完成 + 状态 failed」，而卡片按事件名判成败 —— 所以只有卡片上那行关键事实写着 failed。运行整体会正确地转成失败色。
- 「团队」页是演示数据。上面的 Agent 卡片、成功率、任务数、token 数都是写死的示例；推荐或自选团队的结果不会发给后端。真实运行永远只有一个 agent。
- 「验收标准」不会发给 agent。后端只接收需求正文。你填的标准只留在本地（会出现在「需求」折叠条和导出的运行记录里）。
- 「分派与上下文」里的 ContextPack 是占位。每次运行都一样，也没有喂给 agent。它不是记忆。
- Checkpoint 不能回滚。事件里的 commit 和分支是写死的占位值，后端自己标着「仅在内存里、未实现恢复」。Polaris 没有回滚能力。
- 「议会 / 合议」在今天的真实运行里不会触发，那一页恒为空态。
- 只有 Claude Code 一个 agent。打包版只随包分发它，界面上没有 agent 选择器。
- 项目、任务、文件树都不跨应用重启保存。磁盘上的文件当然还在，但重启后要重新「打开文件夹」。
- 导出的运行记录不能导回应用。它是只读审计快照，不是项目存档。
- Python 终端不是真正的 TTY。Windows 上没有真正的中断信号（停止 = 强制终止进程），curses 这类要求真 TTY 的程序跑不了。终端里也没有 shell，`pip install` 这样的命令打不进去 —— 装包的办法见「Python 终端」那一篇。

## 常见问题

### Agent 说它写了代码，文件在哪？

先看步骤轨的「产出」卡：那里列的是后端登记过的文件名。点开文件页能看到绝对路径，右上角可以在文件管理器里定位它。

产出卡是空的，不代表它什么都没写。有两种可能：一是它只给了文字回复、没真的写文件（而那段正文今天拿不到）；二是它用命令把文件写下去了 —— 那种写法不产生产物记录，运行甚至会被判失败，但文件是真的在磁盘上。

所以先 `git status` 看一眼，再决定要不要重提。真要重提，把需求写得更具体（说清要改哪个文件、要新建什么文件）。

### 左边的文件树里为什么只多了一个文件？

树只补挂后端选中的那一个产物，而且它是打开项目时扫出来的一次性快照，不会自动刷新，也没有刷新按钮。

想让它跟上磁盘：把项目从侧栏删掉（不删磁盘文件）再重新打开。以磁盘为准 —— 去项目目录里看，或者 `git status`。

### 界面十几秒不动，是卡住了吗？

先看状态栏的事件通道。显示「已连接」就说明通道活着，界面不动等于后端确实没事发生 —— agent 真正干活的那几十秒里，后端一条事件都不发。显示「已断开」才是真出了问题。

另一种可能是它在排队：所有需求在「Agent 执行」这一步是串行的，第二个要等第一个跑完。界面显示不出「排队中」，秒表还会照走，但那段时间它并没有在干活。

### 刚提交就失败，或者什么都没发生？

先检查 API key：没配好时应用顶部会有一条提示条。改完 key 后端会自动重启。

另外，后端进程退出或重启时，正在跑的运行会被就地标成失败并写明原因 —— 那句原因就写在主句上。

还有一种情况：agent 干完了活，但它是用命令写的文件，一个产物都没登记 —— 后端会因为「没有可选产物」把这次运行判成失败。先去磁盘上看一眼再说。

### 怎么停下正在跑的 agent？

停不了。驱动没有实现中断，所以界面上没有取消按钮 —— 给一个点了也停不下来的按钮，比不给更糟。

真要停：退出应用。它会杀掉整棵进程树。已经写下的文件不会被撤销，也不会回滚（checkpoint 是占位）。

### 我能不能让它先给我看一眼再写？

不能。没有写入前确认，没有同意 / 拒绝按钮，agent 的权限请求由 Polaris 自动放行。它还有一条不受限制的命令执行通道。把它指向一个有版本控制的目录，是你唯一真正的保护。
