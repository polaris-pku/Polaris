# Python 终端

## 它是什么

在 Polaris 里直接运行当前项目里的 `.py` 文件，输出实时流回下方的终端。

它不是系统 shell。它只能做两件事：运行你项目目录里的 Python 文件，或者打开一个交互式 Python。用的解释器只能是你自己选定的那一个。

> 为什么这样设计：这个终端的执行权是焊死的 —— 只能跑你亲手点的、项目目录里的一个 `.py` 文件，用你亲自选定的那个解释器，而且它拿不到 `ANTHROPIC_*` 之类的环境变量。这是刻意的，不是没做完。

> 但要说清楚这条边界管的是谁：它管的是你这一侧 —— 「Polaris 界面上的执行」永远由你发起。它并不限制 agent。agent 自带命令执行工具，能在任意目录跑任意命令，Polaris 还会自动放行它的权限请求。别把这个受限终端读成「agent 写下的代码跑不起来」——它不需要借用这里。详见「总览」的「动手之前」。

这个终端永远不会自动运行任何脚本 —— 每一次执行都必须由你亲手点一下。

## 快速开始

1. 选一个解释器：打开下方 Dock 的「运行时」频道；没有 Python 就点「安装 Python 3.13.14」。
2. 在左侧文件树里，把鼠标移到一个 `.py` 文件上，点行尾的 ▶。
3. 看输出。要停就点 ■。

## 选择解释器

解释器有三种来源，都列在 Dock 的「运行时」频道里：

- Polaris 下载：由 Polaris 自己下载、自己管理的独立 Python。推荐用这个 —— 它与系统 Python 完全隔离，装包不会污染系统环境。
- 系统已装：从系统里探测到的 Python。Polaris 只是用它，不会去修改它，也不提供卸载。
- 手动指定：你在系统对话框里亲手选中的解释器（比如某个 venv 里的）。

状态栏右侧随时显示当前解释器，点它就能换。

> 出于安全考虑，只有你亲手在系统对话框里选中的解释器才会被允许运行。渲染层不能凭一个字符串路径指定解释器 —— 这条 API 不存在。

## 安装一个 Python

- 来源：python-build-standalone（astral-sh 维护的官方独立构建，自带 pip）。
- 可选版本：3.13.14（推荐）与 3.12.13。
- 体积分平台，差得很远：Windows x64 约下载 45 MB、安装后 126 MB；macOS（Apple Silicon）约 24 MB / 67 MB；Linux x64 约 114 MB / 318 MB。「运行时」频道里显示的是你这个平台的实际体积，以它为准。
- 落在 Polaris 自己的用户数据目录里；不写系统 PATH、不动注册表、不碰系统 Python。
- 下载完会做 SHA-256 校验，校验和是随代码一起提交的常量。校验不通过绝不安装。
- 卸载 Polaris 不会自动删掉它 —— 想释放这几百 MB，在「运行时」频道里点「卸载」。

安装过程会如实报出所处的阶段（下面的数字是 Windows x64 的样子）：`下载 12.4 / 44.9 MB` → `校验 · SHA-256` → `解包 · 1,204 / 3,881 个文件` → `● 已就绪`。

## 运行一个文件

等价于在项目根目录下执行：

```
python -u <你的文件>
```

- 工作目录 = 项目根目录 —— 和 Agent 写文件的目录是同一个。所以脚本里的相对路径（`open('data.csv')`）读到的就是 Agent 写下的那个文件。
- `-u` 表示不缓冲：输出是一行一行实时出来的，不会等到进程结束才一次性刷屏。
- `input()` 可以用 —— 直接在终端里打字、回车。

## 交互式 Python（REPL）

在终端频道空态里点「打开交互式 Python」，等价于：

```
python -i -u
```

和普通 REPL 一样：打一行、执行一行。不是完整的 TTY，所以没有语法高亮和 Tab 补全。

## 装第三方包

对着你当前选中的那个解释器装：

```
<解释器> -m pip install <包名>
```

在交互式 Python 里也可以直接：

```
import subprocess, sys
subprocess.run([sys.executable, '-m', 'pip', 'install', 'requests'])
```

只影响这一个解释器，不影响系统环境。

## 已知限制

- Windows 上没有真正的中断信号：按钮因此叫「停止」而不是「中断」：它会直接终止进程，不会打印 `KeyboardInterrupt`。在 macOS / Linux 上按钮叫「中断」，发的是真的 SIGINT，Python 会照常打出 `KeyboardInterrupt`。我们不假装两个平台一致。
- 不是完整的 TTY：靠光标控制的程序（curses、进度条重绘、`clear`）不能正常工作。逐行输出的程序都正常。
- 输出超过 2000 行会被截断，并显示一条截断提示。这是为了防止 `while True: print('x')` 把界面卡死。
- 只能运行项目目录内的文件：项目之外的路径会被拒绝。
- 中文列对齐依赖等宽中文字体：装了 Sarasa Mono SC（更纱黑体）时汉字恰好是西文的两倍宽，表格才对得齐；没装时会回落到 Consolas 一类字体，中文表格可能错位。我们不假装能保证对齐。

## 常见问题

### 找不到 Python？

「运行时」频道会如实显示「未检测到 Python」，而不是偷偷回落到某个碰巧能跑的解释器。点一键安装，或者「我已经有 Python」手动指定一个。

### 装完还是跑不了？

先看「运行时」频道里那个解释器有没有被选中（行首是实心点）。手动指定的解释器如果被你移动或删除了，Polaris 在下次启动时会重新校验它，校验不过就会降级成「未选择」，需要你重新指定。

### 中文乱码？

不会。子进程的 `PYTHONIOENCODING` 已经默认设成 `utf-8`，`PYTHONUNBUFFERED` 也已设好。如果你的脚本里自己改了编码，那以你的为准。

### 为什么不能运行项目外的文件？

因为这个终端代表的是「你」按下的那次执行：它该跑的只有你看得见、点得到的那个项目文件。允许任意路径，等于把一个受限执行器变成一个通用 shell，而它是带着你的桌面环境跑的。

（这条边界不是用来挡 agent 的 —— agent 有自己的命令执行通道，挡不住，见「总览」。）

### 为什么 Polaris 不能自动帮我跑 Agent 写的脚本？

因为「执行」这件事必须有一个人类的手势。如果后端事件能触发一次执行，那么后端（或它转发的任何东西）只要发出一个事件，就能让宿主替它跑一段代码 —— Polaris 界面上的执行只能由你的一次点击触发：没有 file-watch，没有自动重跑，没有例外。

### 终端里的会话去哪了？

子进程活在主进程里。切页、刷新界面都不会杀掉它；重新打开终端频道时，已有会话和它们的输出会被重新挂载回来。关闭窗口或退出应用时，所有会话会被按进程组彻底清理 —— 不会留下孤儿 python 进程。
